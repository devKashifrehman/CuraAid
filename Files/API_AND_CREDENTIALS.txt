 1b. HOW FRONTEND CONNECTS TO BACKEND (separate domains)
--------------------------------------------------------------------------------
  1) Frontend/my-react-app/.env
         REACT_APP_API_BASE_URL=http://localhost:8000
     (or http://127.0.0.1:8000 — both hit the same Laravel serve)
     After changing .env you MUST restart `npm start`.

  2) Frontend/my-react-app/src/api.js
         axios baseURL = `${REACT_APP_API_BASE_URL}/api`
         Authorization: Bearer <token from login>
     Auth pages (Login/Signup/AdminLogin) and FeedbackForm also read the same
     env var (fallback was the old production host — do NOT rely on that locally).

  3) Backend CORS
         Laravel default allows api/* from any origin (*).
         Local FE on :3000 can call BE on :8000 without custom cors.php.

  4) Backend FRONTEND_URL (backend/.env)
         FRONTEND_URL=http://localhost:3000
         Used for password-reset email links (MAIL_MAILER=log → laravel.log).

  5) Backend APP_URL (backend/.env)
         APP_URL=http://localhost:8000
         Storage/avatar URLs: {APP_URL}/storage/... via frontend fileUrl().

  --- Deploying on REAL separate domains (production) ---
    Example:
      Frontend: https://app.yourdomain.com
      Backend : https://api.yourdomain.com
    Steps:
      a) Frontend .env / build env:
           REACT_APP_API_BASE_URL=https://api.yourdomain.com
         then: npm run build  (serve the build/ folder)
      b) Backend .env:
           APP_URL=https://api.yourdomain.com
           FRONTEND_URL=https://app.yourdomain.com
           GOOGLE_CLIENT_ID=<same client id as frontend>
      c) If you tighten CORS later, allow origin https://app.yourdomain.com
         for paths api/* (and enable credentials only if you switch to cookies).
      d) Google OAuth console: add both domain origins / redirect URIs.

 7. WHAT WORKS NOW (API-wired vs mock) — UPDATED 2026-09-16
--------------------------------------------------------------------------------
  PDF SCOPE (CuraAid thesis) is implemented end-to-end:

  Patient: signup/login, profile, Initial Guidance Chatbot (/ai-health-guide)
  ranked by specialty + rating + experience + availability; book video/audio/chat/physical
  appointments (pending doctor approval); text chat + real WebRTC audio/video in
  Virtual Clinic; e-prescriptions; medical records + uploaded reports; case tracking
  (ongoing / completed / revisit); consultation feedback; pharmacy order from
  identified prescription (OCR + catalog + latest e-prescription).

  Doctor: verification documents; availability + max appointments/day; approve/reject
  bookings; online consult (text/audio/video); notes/diagnosis/treatment/e-prescription;
  recommend physical revisit; patients, prescriptions, analytics dashboard.

  Admin: doctor verification, users (warn/suspend/block), complaints, feedback,
  appointment oversight (GET /api/admin/appointments), platform analytics,
  pharmacy catalogue CRUD + order status.

  API-WIRED:
    - Auth, dashboard (real weekly analytics), appointments, consultations, prescriptions
    - Medical records page at /records
    - Pharmacy catalogue + POST /api/pharmacy/identify + POST /api/pharmacy/orders
    - Admin POST/PUT/DELETE /api/pharmacy/medicines (persisted catalogue)
    - Admin GET/PATCH /api/admin/pharmacy-orders
    - WebRTC signaling: /api/consultations/{id}/call/*

  HONEST LIMITS:
    - Card checkout is recorded as paid (no Stripe/PayFast gateway)
    - WebRTC uses Google STUN; two users on the same consultation must both be online
    - Image OCR uses Tesseract.js in the browser (needs network for first CDN load)
    - Pharmacy cart is stored in the browser until checkout
